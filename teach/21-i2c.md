# 21 · I2C 主机：总线扫描 + 寄存器读写

> 代码：[src/bin/21_i2c.rs](../src/bin/21_i2c.rs)　运行：`cargo run --release --bin 21_i2c`

## 涉及的东西

| API | 说明 |
| --- | --- |
| `I2c::new(I2C0, Config::default().with_frequency(Rate::from_khz(100)))` | 建总线（速率用 `Rate` 表达） |
| `.with_sda(pin)` / `.with_scl(pin)` | 指定引脚 |
| `I2cAddress::SevenBit(0x3C)` | 7 位地址（枚举，不是构造函数） |
| `i2c.write(addr, &[..])` | 写 |
| `i2c.write_read(addr, &[reg], &mut buf)` | 先写寄存器地址、紧接着读 —— 读传感器/OLED 的标准套路 |

## 接线

```
SDA ── GPIO4
SCL ── GPIO5
两者各接 4.7kΩ 上拉到 3V3（很多模块板载已有上拉）
```

不接器件也能跑：扫描结果会打印「没有发现任何器件」，这是正常现象（不是报错）。

## 预期

```
开始扫描 I2C 总线…
  发现器件：0x3C
  读 0x3C 寄存器 0x00 → [00, 00, 00, 00]
```

（具体地址取决于你接的器件；`0x3C` 是常见 OLED 的地址。）

## 关键点

- **用「空写」探测器件**：只发地址不发数据，器件回 ACK 就说明在线。这就是扫描器的原理。
- **地址冲突**：同一条总线上两个器件地址相同就必然通信失败；多数模块用跳线/焊盘改地址。
- 总线卡死（SDA 被从机拉低不放）时，`I2c::new` 之后的第一次访问会超时；断电重启或降速（50 kHz）通常能恢复。
