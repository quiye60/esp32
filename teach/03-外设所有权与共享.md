# 03 · 外设所有权：句柄、共享、中断

## 3.1 `peripherals` 是钥匙串，每个句柄都是 move-only

```rust
let peripherals = esp_hal::init(config);                       // 拿到整串钥匙
let mut led = Output::new(peripherals.GPIO2,                   // 把 GPIO2 这把钥匙"交出去"
                          Level::Low,                          // 初始电平：低
                          OutputConfig::default());            // 推挽输出、默认驱动能力
```

`Output::new` 把 `peripherals.GPIO2` **move** 走了。之后你再写 `peripherals.GPIO2`，编译器会报
`use of moved value`——这是故意的：

- 同一个外设不可能同时被两个驱动持有，所以"两个任务抢同一个引脚/外设"在编译期就不可能发生。
- 对比 C：随手写寄存器、两处代码抢同一个外设，是嵌入式最经典的玄学 bug 来源。

想再拿一份？拿不到。要共享，只能用下面三种办法。

## 3.2 三种共享手段

### 手段 1：简单标量 → `AtomicU32` / `AtomicBool`

```rust
use core::sync::atomic::{AtomicU32, Ordering};

static HEARTBEATS: AtomicU32 = AtomicU32::new(0);   // 可以在任何上下文访问，不需要锁

HEARTBEATS.fetch_add(1, Ordering::Relaxed);          // 加 1
let n = HEARTBEATS.load(Ordering::Relaxed);          // 读
```

适合计数器、标志位、心跳。**不适合**结构体、缓冲区。第 09 课的示例就用这个。

### 手段 2：只初始化一次，之后用 `&'static mut` → `StaticCell`

```rust
use static_cell::StaticCell;

static RESOURCES: StaticCell<embassy_net::StackResources<3>> = StaticCell::new();

// 在 main 里初始化一次，拿到 'static 的引用，可以 move 进任务
let resources: &'static mut embassy_net::StackResources<3> = RESOURCES.init(Default::default());
```

- `init` 返回 `&'static mut T`，**第二次调用会 panic**（防止你把同一块内存初始化两遍）。
- 用途：给需要 `'static` 的东西提供存放地（网络栈资源、任务用的大缓冲、第二核的栈……）。
- 关键：静态变量的生命周期是 `'static`，所以借出来的引用可以进任务、进中断。

### 手段 3：需要共享可变状态 → `critical_section::Mutex<RefCell<T>>`

项目里已经有 `critical-section` 依赖（esp-hal 也实现了它，见配置项
`ESP_HAL_CONFIG_IMPL_CRITICAL_SECTION`）：

```rust
use core::cell::RefCell;
use critical_section::Mutex;

static STATE: Mutex<RefCell<u32>> = Mutex::new(RefCell::new(0));

// 读改写：
critical_section::with(|cs| {
    let mut v = STATE.borrow_ref_mut(cs);      // 注意方法名是 borrow_ref_mut，不是 borrow_mut
    *v += 1;
});
```

- 进临界区时会关中断（很短，别在里面干重活，尤其别打印）。
- `RefCell` 提供运行期借用检查，`borrow_ref_mut` 就是 `RefCell::borrow_mut` 的改名版。
- 这种写法**中断里也能用**，所以它是"主程序 + 中断"共享数据的标准解。

## 3.3 中断里怎么写

```rust
use esp_hal::gpio::{Event, Input, InputConfig};           // Input = 输入引脚句柄；Event = 边沿/电平事件
use esp_hal::handler;                                     // 标记中断处理函数（需 esp-hal 的 unstable feature）
use esp_hal::interrupt::{Interrupt, Priority, enable};    // 中断号、优先级、打开中断（同样需 unstable）

#[handler]                                                // 展开成正确的中断入口（别自己写 no_mangle）
fn on_gpio() {
    // 这里能做的事很少：改 AtomicX、进 critical_section 改状态、标记事件……
    // 不要打印、不要 delay、不要 .await
}

// 在初始化里：
let mut button = Input::new(peripherals.GPIO9, InputConfig::default());
button.listen(Event::FallingEdge);                        // 让 GPIO 外设在下降沿产生中断
enable(Interrupt::GPIO, Priority::Priority1);             // 打开 GPIO 中断（S3 有 Priority1~3）
```

要点：

- 中断函数**不能**有参数、不能 `.await`。它只是在"硬件事件发生"时被 CPU 插进去执行的一小段代码。
- 想在中断里给 async 任务发信号，用 `AtomicBool` + 任务里轮询，或者用 embassy 的
  `embassy_sync::signal::Signal`（需要把 `embassy-sync` 加进 `Cargo.toml`）。
- 如果中断里要访问的数据也需要主程序访问 → 用 3.2 手段 3 的 `critical_section::Mutex<RefCell<T>>`。
- GPIO 的异步等待是另一条路（不需要你写中断）：`esp-hal` 的 `Flex::wait_for_high()` /
  `wait_for_edge()` 是 `async` 的，配 `unstable` 就能直接在任务里 `await`（见 `esp_hal::gpio` 文档）。

## 3.4 `Peripherals::steal()`：逃生舱，危险

```rust
let p = unsafe { esp_hal::peripherals::Peripherals::steal() };   // 绕过"只能初始化一次"的保护
```

它会给你第二份钥匙串，也就彻底绕过了 3.1 的所有保证。只有在非常特殊的场景（例如必须从深层模块
拿到某个外设，且你自己论证过不会重复使用）才用，并且写清注释。新手期建议：**别用**，
把 `peripherals` 一层层传下去就好（外设句柄都是可以 move 的，传参不丢人）。

## 3.5 一段可以直接抄的分配模式

```rust
// main 里：一次性把该初始化的都初始化好，然后把所有权分配给需要它的地方
let mut led = Output::new(peripherals.GPIO2, Level::Low, OutputConfig::default());  // 给 main 自己用
let i2c = I2c::new(peripherals.I2C0, I2cConfig::default()).unwrap();                 // 给 i2c_task 用（返回 Result）
spawner.spawn(i2c_task(i2c).unwrap());                                              // 所有权随参数移交
```

记住一句话：**外设句柄的所有权流向，就是你程序结构的真实拓扑**。想不清楚怎么放，就画一下"谁持有谁"。
