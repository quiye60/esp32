## 1. 第 13 课：RTT 链路

```bash
cargo run --release --bin 13_hello_rtt
```

**接线**：只需调试器（板载 USB-JTAG 或 esp-prog）。
**通过标准**：每秒一行 `第 N 次心跳，开机 NNNN ms`，`开机`数值每秒 +1000 左右。

> 这一步同时验证了"共享 lib 方案"：panic 处理器和 `esp_app_desc!` 都在 `src/lib.rs` 里。
> 已用 `xtensa-esp32s3-elf-objdump -h` 确认过 `.flash.appdesc` 段在 ELF 里；真机启动正常就说明 bootloader 认这个固件头。

**可选加固测试**（测 panic 打印）：在 main 的 `boot::init();` 后面临时加一行 `panic!("panic 测试");`，
重新 `cargo run`，应该看到 `panic: panicked at src/bin/13_hello_rtt.rs:NN: panic 测试` 然后停住。
测完把那行删掉。

## 2. 第 14 课：GPIO 输出

```bash
cargo run --release --bin 14_gpio_output
```

**接线**：GPIO2 → 限流电阻（220Ω~1kΩ）→ LED 正极；LED 负极 → GND。不接也能验证打印。
**通过标准**：先 3 行 `[阻塞]`（LED 约 300 ms 翻一次），再每秒一行 `[异步]`；灯的实际亮灭与打印一致。

**重点观察**：从"阻塞"切到"异步"的那一瞬间没有卡住 —— 说明 `esp_rtos::start` 的时基起来了。

## 3. 第 15 课：GPIO 输入

```bash
cargo run --release --bin 15_gpio_input
```

**接线**：GPIO9 → 按键 → GND。
**通过标准**：

- 前 10 行 `[轮询] 按键 = ...`，按住按键时显示"按下"，LED 跟着亮；
- 之后按下/松开各打印一行 `[异步] ...`，不用一直按着也能捕捉到短按。

**重点观察**：轮询阶段快速点一下按键可能被漏掉，异步阶段不会 —— 这就是这课要理解的差别。

---

## 4. 第 16 课：GPIO 中断

```bash
cargo run --release --bin 16_gpio_interrupt
```

**接线**：同第 15 课（LED + 按键）。
**通过标准**：LED 每 500 ms 闪一次（主循环没被中断拖慢）；每按一次键多一行 `按键中断累计 N 次`，N 严格 +1（不是一次按出好几行）。

**重点观察**：主循环的闪烁节奏完全不受按键影响 —— 这证明 ISR 足够短。

## 5. 第 17 课：时间 API

```bash
cargo run --release --bin 17_time_delay
```

**接线**：无。
**通过标准**：

- `1) delay_millis(200) 实测 …… us`：数值略大于 200000（200 ms）即可；
- `2) Rate::from_khz(24) = 24000 Hz`；
- `3) Timer::after(500ms) 开始等…` 之后约 0.5 s 打印"等到了"；
- `Ticker` 4 拍之间间隔约 250 ms（用打印里的"开机 ms"差值看）；
- `4) with_timeout(300ms, 等1s) → 超时 Err（预期）`；
- 最后停在 `17 课演示结束，程序进入空闲循环`（不再刷屏，属正常）。

## 6. 第 18 课：任务与同步

```bash
cargo run --release --bin 18_embassy_async
```

**接线**：LED + 按键（同第 16 课）。
**通过标准**：

- 每 500 ms 一行 `[main] 收到读数 N，累计 = …`，累计值是 1、3、6、10…（三角数，说明共享状态没被写坏）；
- 按键按下时，先出现 `[button_task] 检测到按下 → 通知 led_task`，紧接着 `[led_task] LED = 亮/灭`；
- 数据流（Channel）和通知（Signal）互不干扰，都在稳定推进。
