## 1. 第 19 课：UART 回环

**接线**：GPIO17（TX）—— 跳线 —— GPIO18（RX）

```bash
cargo run --release --bin 19_uart
```

**通过标准**：RTT 出现 `1) 阻塞模式…` → `收到 8 字节：BLOCKING`；随后每秒一行 `异步收到 7 字节：[41, 53, 59, 4E, 43, D, A]`（`ASYNC\r\n` 的字节）。

拔掉跳线再试：阻塞那段会卡住（`read` 一直等）——这本身就说明了「阻塞」的含义。

## 2. 第 20 课：USB-Serial-JTAG

```bash
cargo run --release --bin 20_usb_serial_jtag
```

**通过标准**：RTT 打印「已通过 USB 串口发出问候语」；另开终端 `screen /dev/ttyACM0 115200`（Windows 用串口工具开对应 COM 口）能看到 `hello from USB-Serial-JTAG!`；在串口里敲字符 → 原样回显，同时 RTT 出现 `收到 N 字节`。

## 3. 第 21 课：I2C 扫描

**接线**：SDA=GPIO4、SCL=GPIO5（各接 4.7kΩ 上拉到 3V3；不接器件也行）

```bash
cargo run --release --bin 21_i2c
```

**通过标准**：

- 没接器件 → `没有发现任何器件（检查 SDA/SCL 接线和上拉电阻）`，每 3 秒重复；
- 接了器件（例如 OLED）→ 打印 `发现器件：0x3C` 之类，并尝试读寄存器 0x00（读失败也正常，不同器件寄存器布局不同）。

## 4. 第 22 课：SPI 回环

**接线**：GPIO11（MOSI）—— 跳线 —— GPIO13（MISO）；SCK=GPIO12

```bash
cargo run --release --bin 22_spi
```

**通过标准**：`发出：[...]` 与 `收到：[...]` **完全相同**（每 2 秒一组，数据每次 +1 变化）。拔掉跳线后收到的变成 `00`/`FF`。

## 5. 第 23 课：trait 抽象层

**接线**：LED→GPIO2（同批 1）

```bash
cargo run --release --bin 23_traits
```

**通过标准**：LED 闪 3 次（由通用函数 `blink()` 完成），RTT 打印「23 课演示结束，程序进入空闲循环」。

## 6. 第 24 课：ADC

**接线**：电位器两端接 3V3/GND，抽头接 GPIO1（没电位器就用手把 GPIO1 碰 3V3 / GND）

```bash
cargo run --release --bin 24_adc
```

**通过标准**：碰 3V3 → 接近 4095；碰 GND → 接近 0；电位器拧动 → 数值连续变化；悬空 → 数值乱跳（正常）。

## 7. 第 25 课：随机数

```bash
cargo run --release --bin 25_rng
```

**通过标准**：先打印一行 64 位种子，然后每次一个 u32 随机数 + 「这次等 N ms」，且**每轮间隔肉眼可见地不一样**（200~1200 ms 之间）。

## 8. 第 26 课：系统信息 + 主动复位

```bash
cargo run --release --bin 26_system
```

**通过标准**：打印 `复位原因`、`当前 CPU 编号`、`芯片版本`、`Wi-Fi STA MAC`；5 秒后设备主动复位，RTT 重新连上并出现第二轮打印，这次 `复位原因` 是 `SoftwareReset`。

> 小提示：拿笔记下你的 MAC 地址，以后可以当设备 ID 用。
